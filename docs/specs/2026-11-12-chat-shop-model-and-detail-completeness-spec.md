## Problem Statement

Riders using the Global Moto Rentals AI chat encounter intermittent false negatives and missing published details even when matching **Catalog Listings** exist on the public website (see `#230`):

1. **Colloquial & short model searches fail or return noisy matches**: Riders searching for `"Detech Win"` or `"Win"` in Hanoi receive zero matches or miss exact `"Win"` listings—first because riders and language models frequently conflate `"Honda Win"` and `"Detech Win"` (while the curated catalog accurately records `Detech` as the manufacturer), second because conflicting `"Brand Model"` prefixes inside queries fail to override a mismatched `brand` argument, and third because compact substring matching allows `"Win"` to match unrelated **Canonical Model Names** containing those letters (`"Winner"`, `"Africa Twin"`, `"Gold Wing"`).
2. **Shop filters fail on punctuation, hyphens, and diacritics/lossy slugs**: Searching for inventory at shops whose published names contain hyphens (`"Mr-Good Bikes"`, slug `"mrgood-bikes"`) or Vietnamese/accented characters paired with legacy stripped slugs (`"Gia Hưng Motorbike Rental"`, slug `"gia-hng-motorbike-rental"`) fails database `ILIKE` matching after punctuation/diacritic stripping, returning unresolved shop filters and zero listings.
3. **Found listings and shops omit published details already loaded from the catalog**: Motorcycle search tool results omit `engine_capacity_cc` (causing the assistant to state that a published `125cc` engine size is unspecified), and shop search tool results omit `full_address`, `phone`, `website`, and `google_maps_url` (causing the assistant to state that published shop addresses and phone numbers are unavailable whenever it answers from shop search results without making a second shop-detail call).
4. **Identical prompts produce inconsistent answers and lack diagnostic traces**: Leaving chat model sampling at default temperature causes repeated identical prompts to choose different tool parameters across runs, while runtime logs omit request correlation, resolved/unresolved filter states, returned record identifiers, and completion summaries needed to diagnose failed turns.

## Solution

Harden AI chat search resolution, tool payload completeness, model sampling determinism, and request-level observability end to end without altering curated database records or requiring database schema migrations:

1. **Resilient Shop & Model Resolution**: Resolve shop references reliably across hyphen/punctuation differences, diacritics, and legacy vowel-dropped slugs within active shops; introduce curated cross-brand colloquial alias expansion so `"Honda Win"`, `"Detech Win"`, and `"Win"` all match the `Win` model family while preserving and displaying each listing's true curated manufacturer (`Detech`); resolve conflicting leading manufacturer names in `"Brand Model"` queries in favor of the explicit manufacturer named in the query; enforce full alphanumeric token-span boundaries on **Canonical Model Name** matching so `"Win"` matches `"Win"` and `"WIN 125"` (while preserving `XADV` ↔ `X-ADV`, `AirBlade` ↔ `Air Blade`, and `CBR500R` ↔ `CBR 500 R`) without matching mid-word substrings (`"Winner"`, `"Twin"`, `"Wing"`); and order exact canonical model matches ahead of multi-token variants.
2. **Complete Tool Payloads & Strict Filter Guidance**: Include published engine capacity (`engineCapacityCc`) on motorcycle search tool items and published contact/location fields (`address`, `phone`, `website`, `googleMapsUrl`) on shop search tool items using columns already retrieved from the catalog, while tightening tool parameter descriptions so the assistant never invents unstated `brand` or `category` filters or places motorcycle model names into `shop`.
3. **Deterministic Chat Sampling, Non-Definitive Empty-Result Phrasing & Structured Traces**: Pin chat completion sampling to deterministic temperature (`0`), reinforce prompt rules so zero-match searches are framed as no matching **Catalog Listings** found for the searched criteria rather than proof a shop lacks the bike, and emit structured JSON server trace logs correlated by `requestId` across prompt interpretation, tool arguments, resolved/unresolved filters, returned record counts/IDs, and final response metadata.

## User Stories

1. As a rider searching for `"Detech Win"` motorcycles at Hung Motorbike in Hanoi, I want the chat assistant to return all three published Detech Win **Catalog Listings** (`110cc`, `127cc`, `140cc`) with their verbatim **Rental Offers** and relative links, so that I can compare options accurately.
2. As a rider asking for `"Win"` or `"Honda Win"` motorcycles in Vietnam without knowing they are manufactured by Detech, I want search resolution to match published `Win` **Catalog Listings** across the colloquial Honda/Detech Win family while still showing `Detech` as the manufacturer, so that I find the exact backpacker bikes shops actually rent without false brand claims.
3. As a rider searching for `"Win"` motorcycles in a city, I want model matching to match `"Win"` and `"WIN 125"` on full token boundaries and rank exact `"Win"` matches first without matching `"Honda Winner"`, `"Africa Twin"`, or `"Gold Wing"`, so that short model names are not drowned out by unrelated models.
4. As a rider searching for fused or hyphenated model names such as `"XADV 750"`, `"CBR500R"`, `"AirBlade"`, or `"PG1"`, I want full token-span matching to continue matching `"X-ADV 750"`, `"CBR 500 R"`, `"Air Blade"`, and `"PG-1"`, so that spacing and hyphen variations remain seamless.
5. As a rider asking for motorcycles from `"Mr-Good Bikes"` in Hanoi with a `VND` daily price limit, I want shop resolution to match `"Mr-Good Bikes"` (`slug: "mrgood-bikes"`) reliably regardless of hyphens, so that initial and `"same shop"` follow-up price searches return consistent qualifying listings.
6. As a rider asking for motorcycles at `"Gia Hưng Motorbike Rental"` (with or without Vietnamese diacritics), I want shop resolution to match the shop even when PostgreSQL `ILIKE` is accent-sensitive and the stored slug (`"gia-hng-motorbike-rental"`) dropped accented vowels, so that accented shop names never fail with false negatives.
7. As a rider asking for engine sizes, daily prices, and links from motorcycle search results, I want `list_motorcycles` to include each listing's published engine displacement (`engineCapacityCc`), so that the assistant reports `125cc` (or clearly notes when displacement is `null` in the catalog) without needing extra per-bike detail calls.
8. As a rider asking for a rental shop's opening hours, street address, and phone number in a single turn, I want `list_shops` to include published `address`, `phone`, `website`, and `googleMapsUrl` alongside `conditions` and `inclusions`, so that the assistant always returns published contact details and accurately distinguishes fields that are genuinely absent (`null`).
9. As a rider running the exact same search prompt multiple times, I want chat tool selection and filter construction to use deterministic model sampling (`temperature: 0`), so that identical questions consistently invoke the same retrieval filters and return the same qualifying **Catalog Listings**.
10. As a rider whose search returns zero matching **Catalog Listings**, I want the assistant to state that no matching catalog listings were found for those search filters (and link relevant shop/search pages when known) rather than claiming definitively that a shop does not carry the motorcycle, so that I am not misled by narrow search constraints.
11. As a platform maintainer investigating a reported chat miss in production logs, I want every chat turn to emit structured JSON trace logs keyed by a `requestId` (capturing user query, tool arguments, resolved/unresolved filters, returned listing/shop IDs and counts, and final response metadata), so that I can pinpoint whether a failure occurred in prompt interpretation, filter resolution, database retrieval, or response synthesis without database migrations or secret exposure.

## Implementation Decisions

- **Preserve Curated Manufacturer Truth (ADR 0004)**: Do not mutate database `brand_id` values on `Detech` `Win` **Catalog Listings**. Keep `Detech` authoritative in storage and display while expanding search-time colloquial brand-model aliases (`"Honda Win"` ↔ `{Honda, Detech}` + `"Win"`) when resolving brand/model filters.
- **Conflicting `"Brand Model"` Prefix Precedence**: When a `query` string begins with a known catalog brand name (e.g., `"Detech Win"`) that differs from an inferred `brand` argument (e.g., `brand: "Honda"`), prioritize the explicit brand prefix inside `query` (or expand via curated colloquial alias when applicable) instead of retaining a contradictory `brandId` + unstripped `"Detech Win"` model filter.
- **Full Alphanumeric Token-Span Model Matching & Ranking**: Tokenize both candidate **Canonical Model Names** and target model queries at whitespace, punctuation, and letter-to-digit / digit-to-letter transitions. A candidate matches only when a contiguous span of candidate tokens equals a contiguous span of target tokens (supporting both split-to-fused matches like `["x", "adv"]` ↔ `["xadv"]` and fused-to-split matches like `["airblade"]` ↔ `["air", "blade"]`, while rejecting partial mid-token substrings like `"win"` inside `"winner"`, `"twin"`, or `"wing"`). When multiple canonical models match (e.g., `"Win"` and `"WIN 125"`), rank exact normalized model matches ahead of multi-token variants before pagination slicing.
- **Accent-, Punctuation- & Lossy-Slug-Resilient Shop Lookup**: Enhance shop reference resolution and shop text search so hyphenated names (`"Mr-Good Bikes"`), unhyphenated slugs (`"mrgood-bikes"`), accented names (`"Gia Hưng Motorbike Rental"`), and legacy vowel-stripped slugs (`"gia-hng-motorbike-rental"`) all resolve within active shops—combining raw + punctuation-preserved query clauses with scoped candidate evaluation (and consonant/normalized-key fallback within the resolved city/country or cached active shop directory) without loading heavy shop fleets or editorial sections.
- **Zero-Extra-Query Tool Payload Completeness**: Expose `engineCapacityCc` (`number | null`) on every item formatted by `list_motorcycles` and expose `address`, `phone`, `website`, and `googleMapsUrl` (`string | null`) on every item formatted by `list_shops`, sourcing directly from columns already selected by the underlying motorcycle and shop listing queries so PostgREST egress remains narrow.
- **Tool Schema Guardrails**: Refine `list_motorcycles` parameter descriptions to instruct the model to populate `brand` and `category` only when explicitly specified by the rider, keep model/bike names in `query` (never `shop`), and rely on `address`/`phone` fields in shop results, distinguishing `null` fields as unlisted rather than guessing.
- **Deterministic Sampling & Structured JSON Trace Logging**: Configure chat completions with `temperature: 0` and generate a per-request `requestId` returned in the chat API response payload. Emit structured JSON `console.info` events for tool execution (recording `requestId`, tool name, raw arguments, resolved filter summary / `unresolvedFilters`, `total`, returned item IDs, and duration) and request completion (`requestId`, bounded user prompt preview, tool call count, `finishReason`, response character length, and truncation flag), strictly excluding API keys, authorization headers, cookies, or client IP addresses.
- **ADR Update**: Extend ADR 0020 to record colloquial brand-model alias expansion, full token-span canonical model matching/ranking, and hyphen/diacritic-resilient shop resolution alongside its existing strict `unresolvedFilters` contract.

## Testing Decisions

- **Behavioral Seam Principle**: Tests assert observable input-to-output behavior across two existing high-level seams—never internal private helper calls or SQL string formatting details unless verifying narrow PostgREST column projections established by prior egress guardrails.
- **Seam 1 — MCP Tool Executor & Search Services**:
  - Test `list_motorcycles` and `getMotorcycles` / `resolveShopReference` for:
    - `"Mr-Good Bikes"` (hyphenated name, unhyphenated `mrgood-bikes` slug) with `VND` `minPrice`/`maxPrice` filters.
    - `"Gia Hưng Motorbike Rental"` (both accented and ASCII inputs against accented `provider_name` and `gia-hng-motorbike-rental` slug).
    - `"Detech Win"`, `"Honda Win"`, and bare `"Win"` queries resolving to `Detech` `Win` listings (including conflicting `brand: "Honda", query: "Detech Win"`).
    - Full token-span matching: `"Win"` matches `"Win"` and `"WIN 125"` (ranking `"Win"` first) and rejects `"Winner"`, `"Winner X"`, `"Africa Twin"`, and `"Gold Wing 1800"`, while `"XADV 750"`, `"CBR500R"`, `"AirBlade"`, and `"PG1"` continue matching `"X-ADV 750"`, `"CBR 500 R"`, `"Air Blade"`, and `"PG-1"`.
    - Presence of `engineCapacityCc` (`125`, `null` when absent) in `list_motorcycles` tool payloads and `address`, `phone`, `website`, `googleMapsUrl` in `list_shops` tool payloads.
  - Prior art: existing MCP tool unit/integration tests and motorcycle/shop search service tests.
- **Seam 2 — Chat API Route (`POST /api/chat`)**:
  - Test that OpenAI chat completions are invoked with `temperature: 0`.
  - Test that `POST /api/chat` returns `requestId` and emits structured JSON trace logs containing tool arguments, retrieval counts/IDs, `unresolvedFilters` (when present), and final response summary without leaking `Authorization` headers or secrets.
  - Test prompt contract coverage for non-definitive zero-match wording and distinguishing `null` vs. published shop contact fields.
  - Prior art: existing `POST /api/chat` route tests.

## Out of Scope

- Mutating production catalog rows (such as reassigning `Detech` motorcycles to `Honda` or editing shop slugs in Supabase).
- Creating new database tables or SQL migrations for persistent chat telemetry storage.
- Currency exchange-rate conversion across currencies (`VND` ↔ `USD`).
- Real-time stock / booking availability checks with external shop systems.

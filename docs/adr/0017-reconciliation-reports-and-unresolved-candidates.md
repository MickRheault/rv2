# Reconciliation Reports, Unresolved Candidates, and Staged-vs-Completed Crawl Separation (Extends ADR 0006 and ADR 0016)

Change Proposals attach an optional immutable Reconciliation Report (`schemaVersion: 1`) so ingestion agents can submit full inventory accounting—including zero-mutation report-only submissions—while keeping `items[]` strictly limited to validated actionable mutations (`add`, `update`, `delist`) on new-format requests and preserving legacy reportless behavior (`coverage_status = 'unknown'`, `reconciliation_status = 'unknown'`). Discovered motorcycles that cannot yet be published as validated items persist across crawl runs in a dedicated `unresolved_candidates` state machine (`open`, `ready_for_proposal`, `resolved_applied`, `excluded`, `dismissed`, with `flagged_for_review` preserving admin dismissals against contradictory crawl evidence) backed by append-only audit events rather than overloading `shop_agent_configs.extraction_hints`. Review-queue status (`proposal_status`, adding `'acknowledged'` and `'superseded'`) is decoupled from independent `coverage_status`, `reconciliation_status`, and `application_status` dimensions, and new-format `POST /api/agent/change-proposals` requests atomically stage the proposal, report, item links, candidates, and validated hints keyed idempotently by `(shop_id, agent_run_id)` without advancing `shop_agent_configs.last_run_at` or writing `crawl_runs`—leaving crawl completion, slot backoff, and run-quality logging exclusively to `POST /api/agent/tasks/:id/status`.

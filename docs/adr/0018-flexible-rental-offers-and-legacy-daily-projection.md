# Canonical Rental Offers with Attached Extensions and Legacy Daily Projection (Extends ADR 0010)

Supplier pricing options are stored verbatim in a canonical `rental_offers` table supporting coexisting `daily`, `package`, `hourly`, and `monthly` Rental Offers plus child `extension` Extension Charges linked via `parent_offer_id` (`ON DELETE CASCADE`, constrained so extensions never exist standalone or nest under another extension). In JSON payloads across `GET /api/agent/tasks`, `POST /api/agent/change-proposals`, `/api/v1/motorcycles`, `PUT /api/v1/motorcycles/[id]/offers`, and MCP `set_motorcycle_offers`, extensions are nested directly inside their parent offer (`extensions[]`) so standalone extensions are impossible by construction. Different offer types (`daily`, `package`, `hourly`, `monthly`) and labeled variants coexist freely across overlapping durations on the same motorcycle; range-overlap rejection applies only among unlabeled `daily` (`per_day`) brackets in the same currency, while exact duplicate offers and duplicate extensions on the same parent offer are rejected. Fixed-day `package_total` offers (`duration_unit = 'day'`, fixed `days > 1`) expose a deterministically computed read-only `dailyEquivalent` (`round(amount / days, 2)`) alongside the authoritative package total without ever dividing `calendar_month` offers by 30 or extrapolating unquoted durations. Existing `rental_rate_tiers` rows are backfilled into `rental_offers`, and standalone `daily` offers (`billing_basis = 'per_day'`, `duration_unit = 'day'`) deterministically project back to `rental_rate_tiers` and `motorcycle_rentals.rental_rate_per_day` (setting `rental_rate_per_day = NULL` when a motorcycle has no standalone daily offer rather than fabricating synthetic daily rates from packages, calendar months, or hourly blocks); legacy `rates[]` and `/rate-tiers` writes remain supported for daily-only motorcycles but fail with `409 Conflict` whenever the target motorcycle already holds non-daily or extension offers so legacy clients cannot silently wipe them. Summary cards, fleet tables, and detail headers prefer a standalone `daily` offer when present and otherwise render the primary non-daily offer verbatim with its real unit/duration (`for 7 days`, `/ calendar month`, `/ hour`); motorcycles with non-daily offers remain visible in listings and featured queries, daily `minPrice`/`maxPrice` filters match standalone `daily` rates only, and `price_asc`/`price_desc` orders standalone daily rates first, followed by non-daily-only offers, with unpriced listings last.

# Additive Year Range Representation and Two-Pass Generation Matching

We represent a motorcycle listing's **Model Year Range** by keeping `motorcycle_rentals.year` as the start (or single) year and adding a nullable `year_to` integer column with a database check constraint `(year_to IS NULL) OR (year IS NOT NULL AND year_to > year)`, normalizing single-year values so `year_to` is `NULL` when equal to `year`. Because a single rental shop may offer multiple generation pricing tiers of the same canonical model (e.g., `2015–2020` and `2021–2024`), inventory diffing uses two-pass matching: Pass 1 matches by canonical model plus exact `(year, year_to)` tuple, and Pass 2 falls back to model-only matching only when an unmatched crawled bike and an unmatched existing bike of the same model can be paired unambiguously without collapsing distinct generation tiers.
